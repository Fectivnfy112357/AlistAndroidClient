# Alist Android 客户端 — HyperOS 高信息密度 UI 重构设计

- 日期：2026-06-26
- 状态：设计已确认，待用户 review 后进入实现规划
- 目标设备基准：红米 K90 Pro Max 等现代全面屏 Android 手机
- 视觉方向：登录页采用极简 HyperOS 系统感；主 App 页面采用高信息密度 HyperOS 网盘风格

---

## 1. 背景与目标

当前 Android 客户端已经具备 Alist MVP 的主要业务能力，但 UI 仍接近默认 Jetpack Compose / Material3 示例页：页面留白、列表、底部导航、输入框和错误提示缺少统一视觉系统；同时没有完整处理 edge-to-edge、顶部状态栏和底部手势导航小白条，导致在红米 K90 Pro Max 这类全面屏设备上观感和可用性都不足。

本次重构目标是建立一套可复用的 HyperOS 风格设计系统，并重构登录页、文件页、传输页、设置页、预览页和移动/复制目标选择页，让 App 看起来像一个真正可长期使用的现代网盘客户端，而不是默认 Android 模板。

### 成功标准

- 页面内容不顶到状态栏，不被底部小白条或底部导航遮挡。
- 登录页呈现极简、高级、系统 App 风格。
- 文件页呈现高信息密度网盘列表，单屏能显示更多文件项。
- 传输页、设置页、预览页与文件页共享同一设计语言。
- 业务逻辑不重写，不引入不存在的数据或假功能。
- 保留关键测试入口和 testTag，避免视觉重构破坏现有功能验证。

## 2. 已确认的视觉选择

### 2.1 登录页：极简系统感

用户已选择登录页方案 A：极简 HyperOS 系统感。

特征：

- 雾白 / 暖灰 / 淡紫背景。
- 顶部品牌区克制展示 `Alist Cloud`。
- 表单位于大圆角白色卡片内。
- 输入框为柔和填充式，不使用重边框。
- 登录按钮为小米蓝/紫蓝胶囊按钮。
- HTTP 明文连接风险提示保留，但以轻量 banner 展示。
- 页面强调安全、稳定、系统感，而不是营销首页。

### 2.2 文件页：高信息密度 HyperOS 版

用户已选择文件页方案 C：高信息密度版。

特征：

- 顶部更克制，显示当前标题、路径和上传入口。
- 搜索框紧凑，不占用过多垂直空间。
- 文件列表行更紧凑，保留 HyperOS 圆角和浅色卡片质感。
- 文件夹使用右侧 `›` 进入，不使用占空间的“打开”按钮。
- 文件操作使用轻量图标按钮。
- 底部采用悬浮胶囊导航，并完整避开手势导航小白条。

## 3. 范围

### 3.1 本次包含

- 建立 HyperOS 风格设计系统。
- 启用 App 级 edge-to-edge，并统一处理状态栏、导航栏和 WindowInsets。
- 重构以下页面 UI：
  - 登录页
  - 文件页
  - 传输页
  - 设置页
  - 预览页
  - 移动/复制目标选择页
- 替换默认 `NavigationBar` 为自定义悬浮胶囊底部导航。
- 抽取通用 UI 组件，减少页面内重复样式。
- 保留现有 ViewModel、Repository、网络、传输和预览业务逻辑。

### 3.2 本次不包含

- 新业务功能。
- 容量统计、最近文件、AI 搜索等当前没有真实数据来源的功能。
- 多账号、管理员面板、外部网盘管理。
- 平板和横屏专项适配。
- 重写 ViewModel / Repository / API 层。
- 自定义字体文件引入；优先使用系统字体栈。

## 4. 设计系统

### 4.1 主题层

扩展 `ui/theme`，从单一 `AlistBlue` 变成完整主题定义。

建议文件：

```text
ui/theme/Color.kt
ui/theme/Theme.kt
ui/theme/Type.kt
ui/theme/Shape.kt
```

核心颜色：

- 页面背景：雾白、暖灰、淡紫灰。
- 主色：小米蓝 / 紫蓝，用于登录按钮、选中态、进度条。
- 卡片：白色或轻微半透明白。
- 边框：低对比灰紫。
- 文本：深灰黑主文本、灰紫辅助文本。
- 警告：柔和橙色背景 + 深橙文本。
- 错误：克制红色文本和轻红背景。
- 文件类型辅助色：
  - 文件夹：淡紫/蓝紫
  - 图片：粉橙
  - 文本：青蓝
  - 其他文件：灰蓝

### 4.2 形状与间距

- 页面水平 padding：主页面 14-16dp。
- 卡片圆角：20-26dp。
- 搜索框圆角：16-20dp。
- 底部导航圆角：24dp 左右。
- 文件行图标色块：14-16dp 圆角。
- 列表行高度保持紧凑，优先单屏显示更多内容。

### 4.3 字体层级

- 主标题：较粗、紧凑，适合中文系统 UI。
- 列表文件名：中高字重，单行省略。
- 辅助信息：小字号灰色。
- 按钮文字：中高字重。

## 5. 通用组件

新增或重构 `ui/components` 下的组件。

```text
CloudScaffold.kt
CloudTopBar.kt
CloudBottomBar.kt
CloudSearchBar.kt
CloudCard.kt
CloudListItem.kt
CloudEmptyState.kt
CloudStatusBanner.kt
CloudActionButton.kt
FileTypeIcon.kt
TransferProgress.kt
```

### 5.1 CloudScaffold

职责：

- 统一页面背景。
- 统一处理 `WindowInsets`。
- 为底部悬浮导航预留空间。
- 支持可选 top bar、bottom bar、snackbar/状态提示。

### 5.2 CloudTopBar

职责：

- 展示页面标题、路径/副标题和右侧操作。
- 文件页、传输页、设置页、预览页共享。
- 支持紧凑模式，避免占用太多垂直空间。

### 5.3 CloudBottomBar

职责：

- 替换默认 Material3 `NavigationBar`。
- 悬浮胶囊样式，半透明白背景、轻阴影。
- 选中项为浅紫/蓝色圆角胶囊。
- 自动避开底部手势导航小白条。

### 5.4 CloudSearchBar

职责：

- 替换文件页当前 `OutlinedTextField`。
- 柔和填充背景，无重边框。
- 左侧搜索图标。
- placeholder：`搜索文件或文件夹` 或更短 `搜索`。

### 5.5 CloudListItem

职责：

- 提供紧凑列表行布局。
- 左侧图标色块，中间主副文本，右侧轻量操作。
- 文件页、目标选择页、设置页可复用。

### 5.6 CloudEmptyState / CloudStatusBanner

职责：

- 统一空状态、无网络、错误、搜索提示。
- 避免页面中直接裸露 `Text`。

## 6. 页面设计

### 6.1 登录页

结构：

```text
[状态栏安全区]

Alist Cloud
连接你的私人网盘，安全访问所有文件

[表单卡片]
  服务器地址
  用户名
  密码
  HTTP 明文连接风险提示
  登录 Alist

凭据将保存在本机加密存储中
[底部小白条安全区]
```

行为保持：

- 登录逻辑不变。
- 保存凭据、自动登录不变。
- HTTP 风险提示保留。
- 错误提示改为卡片内 banner 或统一 snackbar。
- 保留关键文案 `登录 Alist`，除非同步调整测试。

### 6.2 文件页

结构：

```text
[状态栏安全区]

我的文件                  [上传]
/ 或 当前路径

[紧凑搜索框]
[无网络/搜索/错误提示条]

[文件列表卡片]
  文件夹/文件行
  文件夹行右侧：›
  文件行右侧：分享 / 下载 / 更多

[悬浮胶囊底部导航]
[小白条安全区]
```

行为保持：

- `viewModel.load("/")` 启动加载不变。
- 点击文件夹进入目录。
- 上传仍用系统文件选择器。
- 下载和分享仍调用现有逻辑。
- 当前目录搜索结果以小胶囊/状态条展示。

文件行规则：

- 文件名单行省略。
- 第二行显示文件夹、大小、更新时间等当前模型可提供的信息。
- 文件夹右侧使用 `›`，减少视觉占位。
- 文件操作图标保留现有 `download_button`、`share_button` testTag。
- 上传按钮保留 `upload_button` testTag。

状态规则：

- 无网络：顶部轻量提示条。
- 加载中：列表区域轻量 loading。
- 错误：卡片式错误状态 + `重试`。
- 空目录：轻量空状态 + 可选上传入口。

### 6.3 传输页

结构：

```text
传输
全部 / 上传 / 下载  可用时显示

[任务列表卡片]
  文件名
  状态 + 失败原因
  进度条
  速度/大小
  取消 / 重试
```

规则：

- 使用紧凑列表行，不做过大的任务卡片。
- 进度条使用蓝紫主色。
- 失败状态使用克制红色。
- 空状态仍显示 `暂无传输任务`。
- 如果当前数据能区分上传/下载，可显示筛选；如果不能，先显示全部任务。
- 取消、重试逻辑不变。

### 6.4 设置页

结构：

```text
设置

[账号卡片]
  当前服务器
  当前账号
  登录/在线状态

[操作分组]
  清理临时预览文件
  退出登录

[范围说明]
  多账号、管理员、外部网盘不在 MVP 范围内
```

规则：

- 设置项使用系统设置列表风格。
- 退出登录使用克制红色文字。
- 清理成功、退出提示使用统一提示，不再裸露堆叠文字。

### 6.5 预览页

规则：

- 使用统一 `CloudTopBar`。
- 下载、外部打开使用图标胶囊按钮。
- 图片/文本预览区域避开状态栏和底部安全区。
- 不改变预览路由和打开方式。

### 6.6 移动/复制目标选择页

规则：

- 复用文件页紧凑列表行。
- 顶部明确当前目标路径。
- 底部确认/选择按钮避开小白条。
- 不改变复制/移动业务逻辑。

## 7. 导航与安全区

### 7.1 MainActivity

`MainActivity` 启用 edge-to-edge。

目标：

- 状态栏透明，图标为深色。
- 导航栏透明或贴合页面背景。
- 内容由 Compose 组件自己处理安全区。

### 7.2 AppNavHost

`AppNavHost` 保持现有路由结构，但：

- `Scaffold` 底部默认 `NavigationBar` 替换为 `CloudBottomBar`。
- 只有文件、传输、设置三个主页面显示底部导航。
- 登录、预览、目标选择页不显示主底部导航或使用页面专属底部操作。
- NavHost 内容区域不直接依赖默认 Material padding，而由 `CloudScaffold` 与页面决定 inset。

## 8. 测试策略

### 8.1 自动化验证

实现后优先运行：

```bash
./gradlew testDebugUnitTest
./gradlew connectedDebugAndroidTest
```

如果本地没有连接设备或模拟器，必须如实报告 connected 测试无法执行。

### 8.2 关键 UI 验证点

- App 启动不崩。
- 登录页显示 `登录 Alist`。
- 文件页上传按钮 testTag：`upload_button`。
- 文件页下载/分享按钮 testTag：`download_button` / `share_button`。
- 传输空状态显示 `暂无传输任务`。
- 底部导航可以切换文件、传输、设置。
- 红米 K90 Pro Max 上内容不压状态栏、不压底部小白条。

### 8.3 回归风险

- 自定义底部导航可能影响导航测试，需要保留可点击文本或语义。
- 替换 `OutlinedTextField` 时要确保搜索输入仍可访问和可测试。
- edge-to-edge 处理不当可能造成重复 padding 或内容被遮挡。
- 列表行变紧凑后，图标按钮点击目标仍需足够大。

## 9. 实施顺序建议

1. 建立主题、形状、颜色、基础组件。
2. 在 `MainActivity` 与导航层启用 edge-to-edge 和自定义底部导航。
3. 重构登录页，验证启动与登录测试。
4. 重构文件页，保留现有 testTag 和业务逻辑。
5. 重构传输页、设置页。
6. 统一预览页和移动/复制目标选择页。
7. 运行单元测试和可用的仪器测试。
8. 在真实设备上人工检查状态栏、小白条和主页面视觉。
